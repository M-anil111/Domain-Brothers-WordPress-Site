# Design QA: checklist and task list

Measured on https://beta.domainbrothers.com in Chromium at 9 widths (320, 360, 375, 414, 768, 1024, 1280, 1440, 1920 px), 30 pages, 270 page-width combinations.
Generated by `tests/qa/design-audit.js` and `tests/qa/design-audit-report.py`; re-run both after each fix.

**Result: 307 of 307 page checks pass.**

## What was fixed (3.144.0 to 3.144.8, 2026-11-22)

First audit: 274 of 312 checks passed. After the fixes and the audit corrections below: **307 of 307**.

Site fixes:
- **Payment plan chooser:** the visible heading is now the only H1 (the theme's hidden contact line is turned into a paragraph); the page uses the 1320px container and its outer frame was removed so the content sits on the 15px gutter.
- **Checkout:** content, the step bar and the Back/Share bar follow the 1320px container with 15px gutters (were 1240px/1290px with 24px, 12-16px on phones).
- **.dbx-wrap on phones:** the card frame and its 26px padding are removed below 768px, so content sits 15px from each side (was 41px) on 12 pages.
- **Sold domain page:** the band sits on the container (was inset a further 15px); the sections below follow the 80/60/45px rhythm with one shared gap (was 34-40px tops and a double gap).
- **Payment terms:** the calculator and CTA cards no longer overflow the phone screen (396px wide at 375px, clipped).
- **Sign-in and register:** the card no longer adds 20/24px to the section padding.
- **Find a domain:** the banner card keeps the section gap below it (was 18px).
- **Home:** hero and listing use the standard spacing (earlier 40px and 32px overrides removed).
- **Services and Brokerage:** the extra page sections (services, vision, start, features, process) follow the 80/60/45px rhythm (were 40-88px); the section after the grey closing band on Services had no top gap.
- **Blog archive and Deals:** one gap instead of a double 90px gap.
- **Buy Now / Make an Offer (DB-12):** fully round pills on every listing template (All Domains had 8px corners).
- **All Domains (found by the regression QA run, 3.144.8):** a name sold through checkout (mycaymanproperty.com) still showed on the For Sale list and in its count, while sorting left it out. The list now leaves out every name the plugin marks sold or not for sale. Full live QA: 398 of 398 pass.

Deployment note: beta was still running the standalone "Domain Brothers UI Fixes" add-on, which switches off the copy bundled in the plugin. Its files matched the bundled copy, so the add-on was deactivated on beta; the plugin now serves these styles. Deactivate the add-on on production too when the plugin is deployed there.

Audit corrections (the first run measured some things the design does not ask for):
- Desktop starts at 992px, the designer's breakpoint in layout.css (the audit used 1200px, so every page failed at 1024px).
- Spacing is judged as the designer's layout system defines it: coloured bands are checked for their inside padding, and every other spacing is the visible gap between neighbouring page sections, including across wrappers, so a shared gap counts once. Components inside a section (calculator, related tools, CTA cards) keep their own spacing, as layout.css specifies.
- The container check accepts a full-width wrapper whose padding gives the 15px gutter (the FAQs page was a false alarm).
- `CACHEBUST=1` adds a throwaway query string so cached pages are skipped right after a deploy.
